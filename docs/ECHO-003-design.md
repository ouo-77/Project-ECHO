# ECHO-003 · 事实修正、时间调节与反思

三个接口回答不同的问题。`EvidenceReview` 判断现在还应相信哪些证据；`Regulation` 按给定时刻计算状态、后果和交互边界；`Reflect` 检查同类任务中能否形成有独立证据支持的建议。三个接口使用同一人物绑定的 SQLite 库。ECHO-002 的原始事件、判断快照和读取接口继续保留，采用修正结果的新调用方使用 ECHO-003 接口。

## 事实与责任的重评价

宿主先以 ECHO 记忆接口写入带来源的独立核验事实，再调用 `apply_finding(proof_id, previous=...)`。复核标签明确人物、目标事件、领域和所见事实。不同批号撤销整条事件，换算错误属于技术失误，任务口径冲突属于误解，认定欺骗要求核验方明确认定知情虚报。系统不会仅由不良结果推断动机。

系统在单一写事务中检查来源白名单、置信度、作用域、时序、重复来源和修订链头。它先保存修订前判断，然后按原相遇顺序从中立状态重放有效经历。撤销的事件不参与任何维度，包括熟悉度及对后续证据施加的折减；改标事件在原位置按新规则计算。结果保存旧标签、新标签、理由、来源、支持与反面证据、变更前后分数及策略。后续独立复核可以引用上一修订进行反转。独立正向来源至少两条、领域分数达到 0.65 才提出沙盘试验，否则请独立复核。配置继承人物绑定的 ECHO-002 规则。关系标签不赋予执行权限。[实现](../echo_memory/reappraisal.py)

## 调节、实际损失与边界

输入时钟为有时区的 UTC 时间，默认使用当前时间。`Regulation.at(domain, when)` 从当时已接纳的事件及复核计算三个领域内的负向激活水平。每项贡献等于事件激活幅度 × 可信度 × 尺度增益 × 2 的负指数衰减，指数为经过天数除以半衰期。求和后加基线并限幅。默认半衰期分别为 1、7、30 天。重启只需重读持久化时间及配置，无须后台计时器。[参数](../echo_memory/regulation_rules.json)

误会澄清会在原事件位置替换错误归责。已独立核验的损失由另一条有目标 ID 的事实记录，损失的短期激活会衰减，未撤销的损失仍降低关系评价。`emotional_recovery` 为一减短期激活；`trust_recovery` 为当前领域分数相对首次原始负面事件时分数的变化量，没有此类事件时参考中立值。宽恕、关系修复与边界分别由有来源的选择记录决定。恢复关系要求双方同意和足够的有效补救经历，仍可维持限制或暂停。历史查询按模拟接纳时间重建，同一选择的更改需引用当前链头。硬删除、隐私限制和原记忆修订会限制当前可读材料；历史查询不提供删除数据恢复。[实现](../echo_memory/regulation.py)

## ECHO Reflect 的三层记忆

| 逻辑层 | 保存内容 | 决策入口 |
| --- | --- | --- |
| Episodic Memory | 复用原经验、核验指针和关系事件，按当前有效标签读取 | 仅接纳显式含 `reflect=allow`、领域、工序、用途与人物绑定的经历 |
| Experience Knowledge | 每个领域和工序的假设版本、前版、生成时间、置信度、来源依赖、反例和审核状态 | `recommend(domain, task, max_tokens=...)` |
| Self Model | 从最新有效版本生成能力评估，列出该工序推导数、独立核验成功及失败数、证据不足和矛盾状态 | `self_model(domain)`，可依版本回查依赖 |

默认至少 3 条训练记录形成方向，至少 2 条独立核验记录验证，相应一致率均需达到 75%。正向占优建议试验，负向占优建议复核；平票不确定。置信度取独立核验成功数加一除以核验总数加二。标签由调用方标出训练或核验用途，来源唯一，适用范围限于同一人物、领域、工序。相同底层来源被伪装成不同来源仍是宿主核验的责任。

高风险、重大影响或风险未注明的记录触发人工审核。只有独立核验通过的现行版本可由独立人审来源签发批准，不足或被反证的版本不能通过批准直接升级。SQLite 触发器在复核写入、原记忆删除、替代或同工序新经历写入时标记待核验。此刻旧建议即退出检索。重评会沿原始事件 ID 重建一版，旧证据链仍可通过 `impact(event_id)` 查询。重复输入相同证据摘要不会提高置信度。模型候选、演绎结果和人审批准都不能作为原始经历参与计数。[模块](../echo_reflect/engine.py) · [数据库约束与触发器](../echo_reflect/schema.sql)

## 调度、取用与可选模型接口

`daily_reflection` 默认相隔 24 小时，每次最多处理 4 个变化范围；`deep_reflection` 默认相隔 168 小时，检查全部可读范围；`event_reflection` 接受已核验的失败、冲突或重大事件 ID。轻量和深度模式均可查同范围历史，以验证新观察。空闲或重复批次没有新版本。调度时间、暂停状态、去重摘要及审计持久化，失败时事务回滚，不消耗成功周期。显式 `tick` 可供宿主定期调用，`watch` 仅在用户启动的本地进程中轮询。暂停停止生成，禁用同时停用经验建议。配置项见模块中的 DEFAULT，创建后绑定数据库。

未来 OpenClaw Skill 可传入经授权的数据库绑定、领域、工序和预算。FTS5 从任务文本的工序标识召回候选，结构化过滤再核对精确工序和领域。歧义、越界、超预算、证据不足及待重评返回空建议。输出包含版本、核验表现和反例数量；历史建议可质疑。已登记暂停的交互边界不允许返回建议，有限边界不允许返回试验建议。实际启动动作仍由宿主单独授权。

可选的模型传输协议默认每天 0 次调用、0 Token。启用时需显式授权且预留输入和最大输出 Token；失败仍占用额度。宿主应使用所选模型的分词器本地计算完整请求开销，并强制执行输出上限。协议只接收范围和证据统计，回答只能写入带来源版本的候选区。交付版本没有 DeepSeek 网络客户端。本次用内存桩验证协议，没有发送外部请求。[候选接口](../echo_reflect/candidates.py) · [命令行入口](../echo_reflect/__main__.py)

在已有、专用且绑定人物的实验库上，手动调度命令为 `python -m echo_reflect --db <实验库> --person <虚构人物ID> tick`。将末项换为 `paused`、`disabled` 或 `enabled` 可调整运行状态。完整重现实验不需要准备持久库，见[实验报告](../experiments/echo003/REPORT.md)。
