# ECHO-002 · 经验如何改变对同一条建议的回应

关系模型回答两个问题：这个人在特定领域的建议有多少经核实的支持？面对下一条建议，模拟器会要求说明方法、对照前例、提出沙盘试验，还是要求独立复核？每项判断都可以回到具体经验。B 模式体现在保留异议及其依据。C 模式中的真实自主行动、授权执行与撤销留给以后独立设计。本模块只返回模拟策略。

## 研究依据与工程取舍

- Jøsang 和 Ismail 的 Beta Reputation System 用正负反馈累计可靠性。ECHO 分别记录一般可靠性和每个领域的正负证据量，引入对称先验和按证据更新的折减。它的分数表达所选规则下的倾向，尚未做概率校准。[原始论文](https://aisel.aisnet.org/bled2002/41/)
- FIRE 区分直接互动、角色、见证和认证等来源。本实验只摄入带核验来源的直接事件。朋友、伴侣式陪伴或家庭标签都不增加专业可信度。[FIRE 论文](https://eprints.soton.ac.uk/262593/)
- EMA 研究事件评价如何影响应对策略。ECHO 用五个有界变量和显式规则实现其中一个可检验的问题：不确定或谨慎状态升高时，模拟策略是否更倾向复核？这些变量没有心理测量标定。[Marsella 与 Gratch 的论文](https://www.sciencedirect.com/science/article/pii/S1389041708000314)
- 开源 Generative Agents 的反思流程先检索节点，再把支持新结论的节点 ID 一并保存。Graphiti 记录事件和矛盾关系。ECHO 复用自己已有的经验记录与来源指针，增加事件账本和反向证据标记。实现由 Python 标准库和 SQLite 构成，未引入两者的代码、提示词、模型或依赖。[Generative Agents 固定版本源码](https://github.com/joonspk-research/generative_agents/blob/fe05a71d3e4ed7d10bf68aa4eda6dd995ec070f4/reverie/backend_server/persona/cognitive_modules/reflect.py#L99) · [Graphiti 固定版本源码](https://github.com/getzep/graphiti/blob/e911422602068a0dc28e72a1961698269e9aefb2/graphiti_core/utils/maintenance/edge_operations.py#L424)

## 什么证据能改变关系

实验为每个虚拟人物建立独立数据库。调用方先通过 `store.add` 记录一条 experience，再调用 `Relationship.observe(memory_id, kind, domain)`。核验范围包括人物、事件类别、领域标签、显式时区、核验来源白名单、来源记录引用和置信度。默认门槛为 0.5。真实世界核验发生在受信任的调用方，本实验由固定合成夹具承担这个角色。

每个库绑定人物 ID 和完整规则配置。单个写事务检查顺序与重放，写入事件及新状态。重复提交相同 ID 和作用域会返回当时的快照，重复来源不能再次记分。经验先单独落库，因此中断后可能有尚未评估的经验，可用同一 ID 重试。较早发生但迟到的事件会被拒绝。研究者可在新库按事件时间重放。

`relation_events` 保存事件类型、UTC 时间、核验来源及引用、可信度、领域、各维度权重、变化原因、冲突标记、记忆 ID 和更新后快照。前后快照可还原实际变化量。共同经历数量在 `shared_experiences`，明细在 `history()`。公开导出仍由原有 ECHO 记忆接口处理。研究者的本地审计接口与模拟人物可用的检索接口分开。

## 状态与参数

初始熟悉度为 0，关系为陌生人，共同经历为空。亲近度、一般与未知领域可信度、五个内部状态均为 0.5。设事件置信度为 c，规则对当前领域或一般可信度的有符号权重为 w，取 s = cw。仅在该维度有证据时更新正、负证据量：

```text
P' = retention × P + max(s, 0)
N' = retention × N + max(−s, 0)
trust' = (prior + P') / (2 × prior + P' + N')
```

默认 prior = 2，retention = 0.92。一般可靠性和每个领域各有独立的一对证据量。新证据的方向与原有净证据 P−N 相反时，账本标记对应维度的冲突；这表示当前证据挑战原判断，不等同于查实人物说谎。调用 `explain()` 或 `explain("metrology")` 可取得分数、两侧证据量及每次更新的依据。

熟悉度按 `f + (1−f) × familiarity_step × c` 增长。亲近度累加该事件的社会影响并限制在 [0,1]。例如，兴趣相投增加亲近度，普通接触只增加熟悉度。严厉而正确的批评同时提供正向领域证据与负向亲近度变化。规则表覆盖帮助、协作项目、爱好、欺骗、批评、可靠建议、专业失误、误解、澄清、修复和普通接触。[全部数值与原因](../echo_memory/relationship_rules.json)

| 内部状态 | 表达的计算含义 | 本次用途 |
| --- | --- | --- |
| curiosity | 探索与追问的倾向 | 观察遇到新兴趣或正确批评后的轨迹 |
| caution | 对核验成本的重视 | 超过阈值时要求独立复核 |
| positive_valence | 对近期互动结果的正向评价 | 观察批评、欺骗与修复的不同影响 |
| uncertainty | 对当前情况的不确定程度 | 超过阈值时要求独立复核 |
| engagement | 参与共同核查的倾向 | 超过阈值时采用邀请共同复核的交互方式 |

每步内部状态沿 `0.5 + affect_retention × (旧值−0.5) + 事件权重 × c` 更新并限幅。默认保留系数为 0.8。关系参数、各事件权重、可信度门槛、来源和决策阈值可在独立配置文件中调整，构造函数接受 `rules=路径`。更换配置时使用新实验库，便于解释不同参数的结果。

## 社会标签、边界与判断

陌生人与熟人的转换只依赖熟悉度。朋友、亲密陪伴者、家人三种称谓均需调用方明确提交双方同意，任何一方撤回后可恢复为按熟悉度推得的标签。`set_policy` 替换完整策略并保存变更记录。同时可关闭证据检索、排除特定领域。被排除领域禁止摄入关系事件和模拟决策；关闭检索后可继续利用已有汇总状态。角色字段只用于描述双方确认的称谓，决策代码不读取角色字段。没有从模型分数通往系统权限、发送消息或调度任务的接口。

决策先看领域可信度、谨慎和不确定状态；熟悉度和参与倾向影响交互方式。允许检索时再取同一人物、同一领域最近的一条有效专业经验，经 ID 连接 ECHO 记忆表，读取核验过的事件标签。负向证据触发独立复核，正向前例可把“请说明方法”改为“对照已验证案例”。每次返回所用 ID。该查询采用结构化检索，不依赖聊天文本相似度。原经验删除或被修订后不再用于这条实时检索路径；旧快照仍是历史判断记录，撤销旧证据影响须在新库重放。

在模拟中只讨论当前任务、证据与验证方法。策略集中没有索取关注、制造排他关系、诱导延长互动或扩大权限的动作。[实现](../echo_memory/relationship.py) · [实验与曲线](../experiments/echo002/REPORT.md)
