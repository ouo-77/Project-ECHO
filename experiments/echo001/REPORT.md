# ECHO-001 · 长期记忆可靠性实验

2026-11-10，Windows，CPython 3.12.6，SQLite 3.45.3。22 道查询中，与标准答案集合完全相符的由 16 道增至 19 道。增加的 3 道都要求匹配非连续术语。两版都漏掉同义表达，也都在一个含糊查询上返回了两条无关记录。

## 实验设计

26 条中文记录全部为本实验编写的合成材料，模拟采样、仪器校准与沙盘演练。虚构用户 A 有 20 条，B 有 6 条。两者具有同名物件和不同事实值。记录包括修订前的历史版本。每次运行用临时目录为两个版本、两个用户分别建库。子进程写入后退出，另一子进程重新打开数据库。没有加载聊天记录、生产配置或调用模型。

基线从 Git 提交 `80d5e27` 原样提取 Python 包。候选版使用本报告所在提交的代码。两版都返回最多 3 条、600 个字符，候选版另设 60 个估算 Token 的上限。索引启用后先对每题预热一次，再以固定题序运行 20 轮，每版计时 440 次。用单调高精度时钟统计完整 Agent 检索响应，含 SQLite 读取和上下文拼接。建库、建索引、启动进程与预热不计入耗时。

逐题答案由固定标注与实际返回的 ID 比较，无关项按每题单独计数。Token 估算按每个非 ASCII 字符 1 个单位、每 4 个 ASCII 字符 1 个单位向上取整，包含 UUID、方括号和分隔符。只计返回给调用方的文本。全程模型 API 调用和计费 Token 均为零。[逐题结果和耗时汇总](results.json) · [查询与标准答案](queries.jsonl)

## 可靠性检查

| 检查 | 观察结果 |
| --- | --- |
| 跨进程恢复 | 两版在新的读进程中均按 ID 恢复全部 26 条，逐条核对正文、类别和时间。候选版另核对来源指针与置信度。 |
| 时间与检索 | 三条采样事实以非时间顺序写入，重要性相等。按事件时间得到夜间、晨间、午间三条记录，ID 顺序为 a03、a01、a02，对应合成日期 5 日、3 日、1 日。 |
| 冲突与修正 | 同键写入第二种照明模式时返回旧 ID。显式修订后当前搜索仅返回 a05，按 ID 可回查 a04，修订关系正确。 |
| 反思回查 | 基线没有从经验 ID 回查的接口。候选版用 a06 得到 a08、a07 两条反思。回归测试另验证修订后旧反思退出当前集合，未知 ID 返回空集。 |
| 用户隔离 | 对每条记录，另一用户的数据库均查不到该 ID。相同关键词在两库分别命中各自的档案盒和滤芯，跨用户的特有标记查询为空。 |
| 索引与隐私 | 回归测试通过已有记录回填、索引启用后写入及导入、删除和重新打开后的检索。公开导出省略本地来源指针。 |

## 失败与局限

- Q12 用“断电”查“停电”，Q13 用“风有多大”查“风速”。两版均返回空集。Q05 只给“校准”，实际意图限定为温箱，两个不相关仪器也被召回。Q20 显式输入“温箱 校准”后才得到唯一正确记录。
- 错误召回率下降来自新增的正确返回。错误条数仍为 2。Q19、Q20、Q22 专门检验多词查询，这三题的收益不能外推为日常自然语言查询的平均收益。Q20 的两个词均很短，走的是字面交集路径。
- 候选版的最长结果收到了预算以内，但新增命中使总量增加 45 个估算 Token。只要返回了 ID 和部分正文，ID 指标就会计为命中。Q01 等查询中末条正文被截断，尚未验证剩余文字能否支持正确回答。
- 延时为单机小样本热读。基线每次检索会执行 schema 初始化检查，候选版在 Agent 建立时启用索引，故耗时差异同时包含连接和初始化策略。未分离 FTS 的独立贡献，未测冷启动、大库写放大、异常断电恢复或真实模型分词。
- 每个用户由宿主指定独立数据库路径。此次验证的是数据文件隔离，线上身份鉴权、访问控制和错误路由仍有待独立验证。
